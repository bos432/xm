# 优化整改方案

> 本文主体记录 2026-07-02 历史整改。当前线上运营门槛见本节 0 的更新结论和 `modernization/QA_REPORT.md`。

## 0. 当前结论

### 2026-10-17 运营复核状态

旧版结论中的“没有 P0/P1 阻塞”只代表当时回归范围，不代表当前可以正式运营。当前本站基础服务正常，但正式申报批次为空；SMTP 仍为 `log`；生产备份日志已证明 OSS PUT/HEAD 长度校验成功，隔离恢复尚未验收；专家评分模板为 100/100，但只确认两条 E2E 专家认证通过记录，未证明有三位正式认证专家；生产六角色浏览器闭环未完成。以上均须在正式受理前关闭，详见 `modernization/QA_REPORT.md`。

以下权限可见整改于早期版本完成；这不等同于本轮六角色生产浏览器闭环已通过：

- 后台取消角色权限后，后端不再用内置默认权限补回。
- 部署 seed 不再覆盖已调整过的角色权限。
- 单位、区县、部门默认不再看到“专家认证”。
- 全周期页面副标题按当前账号可见页签动态展示。
- E2E 增加专家认证权限回归，最终结果 `9 passed`。

历史回归中已完成的代码整改如下；运营验收阻断项仍未全部关闭，不得把本方案解释为“无 P0/P1”。

## 1. 已完成整改

### 1.1 部署稳定性

- GitHub 仓库公开后，生产部署不再依赖 Token。
- 部署脚本完成前端构建、后端依赖安装、缓存刷新和本站 current 切换；常规发布跳过迁移与 Seeder，不 reload Nginx。
- 部署后增加真实登录健康检查。
- `health_check_user` 已可通过 `health:login-check`。

### 1.2 首页与品牌素材

- 首页去除重复“单位注册”，保留“新单位注册”。
- 首页管理支持 Logo、Banner、Favicon。
- 未上传 Favicon 时返回 `favicon_url:null`，使用默认 `/favicon.ico` 兜底。

### 1.3 登录与安全

- 登录接口返回中文限流/锁定提示。
- 返回 `retry_after_seconds`，前端可显示倒计时。
- 安全中心记录登录限流事件。
- 支持白名单和临时放宽登录限流。

### 1.4 项目与全周期

- 项目列表支持 URL query 回显和筛选。
- 全周期支持通过 `/lifecycle?project_id=<id>` 自动回显项目。
- 合同任务书、实施进展、整改闭环、专家认证统一归入全周期。

### 1.5 验收管理

- 验收增加 `待处理 / 已处理 / 全部可见`。
- 区县、部门、专家可查看自己处理过的历史验收。
- 单位只查看本单位验收。
- 管理员和超管查看可见范围内验收。

### 1.6 测试数据治理

- 项目、验收、申报批次支持测试数据筛选。
- 识别规则：
  - `metadata.e2e=true`
  - 名称、编号、标题包含 `E2E-`
- 超管可归档测试批次。
- 不物理删除任何测试数据。
- 修复 `metadata` 为空时 `e2e=0` 误排除正式数据的问题。

### 1.7 E2E 自动化

- 历史自动化曾覆盖公开首页、六角色登录入口/页面权限、项目筛选、全周期、验收历史和安全中心；当前生产六角色项目全流程浏览器闭环尚未完成，详见 `modernization/QA_REPORT.md`。
- 报告按运行批次输出到：

```text
modernization/e2e/reports/runs/<run-id>
```

1. 修改超级管理员默认密码。
2. 上传正式 Logo、Banner、Favicon。
3. 配置正式 SMTP 邮箱。
4. 录入正式申报批次。

12. 确认至少三位真实专家完成资质审核，再启用要求 3 人随机评审的正式项目流程。
13. 使用隔离浏览器与受控账号完成六角色端到端闭环，不要切换共享超管会话。

## 5. 风险提示

- 正式业务上线前不要删除 E2E 数据，否则自动化回归要重新建数据。
- 如果正式批次名称误含 `E2E-`，可能被识别为测试数据。
- 邮件 SMTP 如使用个人邮箱，需要开启授权码，不要使用登录密码。
- 登录风控不要关闭，只通过白名单和临时放宽辅助验收。
